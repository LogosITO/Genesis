# Spatial acceleration research

**Status: experimental CPU and GPU BVH.** `WorldState` owns the world. `Scene` is an immutable renderer snapshot; its BVH is derived acceleration data and is never saved or used by simulation. Sphere, axis-aligned box, and capsule intersections remain analytic. Direct CPU and GPU traversal remain available as references.

The deterministic CPU builder calculates world-space bounds, splits at the median on the widest axis, and breaks equal-center ties by snapshot index. Leaves hold at most four primitive indices. An empty scene has no nodes. The GPU adapter flattens the tree in preorder. Each 64-byte node has four 16-byte vectors: lower bound (`f32`), upper bound (`f32`), metadata (`u32` subtree exit and leaf count), and four snapshot indices. Rust size and offsets are asserted; Naga validates the WGSL shader. The primitive buffer still carries the analytic parameters and stable object identity. Active node and primitive counts are explicit uniforms checked against storage array lengths in WGSL.

The CPU validates child order, subtree exits, leaf ranges, and primitive indices while flattening. Requested bytes are checked before allocation against the configured budget and adapter storage limits. BVH storage is separate from the 64-byte primitive records; the 381-primitive scene uses 255 nodes, 16,320 active BVH bytes, and a 16,384-byte allocation on the measured adapter. These figures exclude render targets, query buffers, and driver overhead.

CPU and WGSL traversal reject a node when its bounds do not overlap the closed ray segment, then call analytic primitive intersections in visited leaves. WGSL walks iteratively: a rejected node skips to its subtree exit; an accepted internal node advances to its first child. This stackless preorder walk has a hard bound of `node_count` visits. It is **not near-first**: sorting each ray's children would require additional state and is not justified by current measurements. The closest hit wins; equal distances select the earlier snapshot index. Invalid WGSL traversal metadata or an exhausted visit bound falls back to GPU direct traversal, never a false miss. An invalid CPU-built tree returns an error before dispatch. The builder uses fallible vector reservation and reports `TooManyObjects` on allocation failure.

`GpuRenderer::draw` selects direct for at most four primitives and attempts BVH above that count. This simple local threshold reflects that one primitive was slower with BVH while 13 were faster in the measured scene; it may need adapter-specific evaluation. `draw_with_traversal` and `query_with_traversal` expose explicit paths for comparisons; `query` stays direct by default. Camera changes do not rebuild the world-space tree. Changed packed geometry invalidates and fully rebuilds it; identical packed snapshots reuse the buffer. No incremental refit is implemented. A snapshot overflow remains an explicit `PrimitiveCapacity` error and cannot silently omit geometry. Automatic mode falls back to direct on BVH capacity/allocation failure; explicit BVH mode reports it.

CPU bounds expand arithmetic endpoints one representable `f64` value outward. GPU node bounds expand converted `f32` endpoints by eight epsilon-scaled units plus one outward representable value; slab entry/exit calculations also receive relative slack. A nonfinite quotient declines to cull. These guards are intended to avoid ordinary false rejection, **not a certified floating-point containment proof** for all supported extreme scales, ray directions, or adapters. CPU `f64` and GPU `f32` can disagree near tangencies and almost equal depths. Direct GPU traversal remains the operational comparison path; broad readback results and their limits are in the [0.6.1 experiment](../research/gpu-bvh-acceleration.md). See also [primitive bounds](../specifications/primitive-bounds.md) and the [CPU/GPU contract](../specifications/cpu-gpu-contract.md).

Camera-frustum culling remains disabled. A center-only test would incorrectly remove long capsules and nearby large primitives. Future culling must cover the complete pixel-ray frustum, near/far planes, transformed bounds, and numerical margins, and must revalidate on camera movement and resize.
