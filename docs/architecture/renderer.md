# Renderer architecture

Foundation 0.7.1 draws the kinematic sphere from the same authoritative body state used by CPU contact. The source marker is visible but is not a physical collider. See the [contact specification](../specifications/kinematic-contact.md).

Foundation 0.8 assigns each of the four bounded organism slots a distinct node/connection color. The First Life viewport shows two organisms and source ledger values in its title. The colors and marker do not determine resource allocation; the source remains [authoritative mathematical state](../specifications/ecosystem-state.md).

## First Structure extension

`Scene::from_world` also copies every parent-child edge as an analytic capsule with stable connection identity. Its endpoints come from `WorldState`; the renderer calculates no growth. CPU and WGSL intersect capsule sides and hemispherical caps directly. Overlapping node spheres and capsules are separate nearest-hit solids and do not form a tested watertight union. See the [capsule contract](../specifications/capsule.md) and [growth model](../specifications/growth-model.md).

**Status: experimental / research stage.** `analytic-renderer` is a leaf crate depending on `math`, `field`, `world`, and `wgpu`. Core crates contain no GPU or window types. `first-light` owns the `winit` window and fixed-step simulation loop. The renderer reads a frame snapshot; it never mutates `WorldState`.

`Scene::from_world` copies current ordinary sphere IDs, transforms, and radii, plus each organism's analytic node spheres, connections, and each resource source's visible marker. It attaches semantic world targets for CPU picking. The default First Light mode adds a static `AxisAlignedBox` through the same validated `Primitive` API with a distinct ID and color; it is renderer-owned and not persistent world state. First Life mode adds no renderer-owned growth object. Every frame rebuilds its snapshot after simulation steps, so visible growth, pruning, and source position come from authoritative `WorldState`.

The snapshot copies all supported world primitives. It converts translation, positive uniform scale, radius, and box half extents to world-space `f32` parameters. A bounded dynamic GPU storage buffer replaces the former 256-object limit. WGSL computes one finite camera ray per pixel, analytically intersects the scene, keeps the closest hit, and writes an RGBA8 storage texture. A three-vertex full-screen triangle copies that image to the swapchain. Its vertices are screen coordinates, not world geometry. The image may also be read back without a window. There is no mesh, voxel, distance marcher, or CSG compiler. Foundation 0.6.1 adds an experimental GPU traversal of the CPU-built BVH, while direct traversal stays available; see [snapshot capacity](../specifications/render-snapshot.md) and [spatial acceleration](spatial-acceleration.md).

The query entry point uses the same WGSL `sphere_hit`, `box_hit`, and `trace` functions as the viewport. Rust uses a separate `f64` analytic implementation as a reference. Shader parsing/validation and GPU layout checks run in ordinary tests; opt-in native tests compare explicit ray classifications, IDs, distances, and normals, including a First Life snapshot, then read an offscreen image. GPU tests are ignored by default so public CI does not require graphics hardware.

`GpuRenderer::new` captures validation errors while compiling pipelines. The application reports adapter/backend/driver, shader and surface errors, resolution, object count, a conservative upper count of per-pixel object tests, fixed ticks, and either current radius or growth-node count. Surface resize reconfigures nonzero windows. Outdated surfaces retry; lost surfaces and device loss exit with diagnostics rather than using stale GPU resources. The prototype does not yet recreate a lost device or surface. GPU compute duration is read from timestamp queries only when the adapter supports them; CPU submission time is reported separately. See the [CPU/GPU contract](../specifications/cpu-gpu-contract.md), [First Light benchmark](../research/first-light-benchmark.md), [First Life measurements](../research/first-life-measurements.md), and [First Scale measurements](../research/first-scale-benchmark.md).
