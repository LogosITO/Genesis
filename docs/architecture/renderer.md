# Renderer architecture

**Status: experimental / research stage.** `analytic-renderer` is a leaf crate depending on `math`, `field`, `world`, and `wgpu`. Core crates contain no GPU or window types. `first-light` owns the `winit` window and fixed-step simulation loop. The renderer reads a frame snapshot; it never mutates `WorldState`.

`Scene::from_world` copies current sphere IDs, transforms, and radii. The example adds a static `AxisAlignedBox` through the same validated `Primitive` API with a distinct ID and color. A frame rebuilds the snapshot after simulation steps, so displayed radius is derived from the authoritative `WorldState` used by CPU field queries. The static box is renderer-owned for this prototype because the world model currently stores spheres only. It is not presented as persistent world state.

The snapshot accepts at most 256 objects. It converts translation, positive uniform scale, radius, and box half extents to world-space `f32` parameters. WGSL computes one finite camera ray per pixel, analytically intersects all objects, keeps the closest hit, and writes an RGBA8 storage texture. A three-vertex full-screen triangle copies that image to the swapchain. Its vertices are screen coordinates, not world geometry. The image may also be read back without a window. There is no mesh, voxel, distance marcher, CSG compiler, or acceleration structure.

The query entry point uses the same WGSL `sphere_hit`, `box_hit`, and `trace` functions as the viewport. Rust uses a separate `f64` analytic implementation as a reference. Shader parsing/validation and GPU layout checks run in ordinary tests; opt-in native tests compare explicit ray classifications, IDs, distances, and normals, then read an offscreen image. GPU tests are ignored by default so public CI does not require graphics hardware.

`GpuRenderer::new` captures validation errors while compiling pipelines. The application reports adapter/backend/driver, shader and surface errors, resolution, object count, a conservative upper count of per-pixel object tests, fixed ticks, and current world radius. Surface resize reconfigures nonzero windows. Outdated surfaces retry; lost surfaces and device loss exit with diagnostics rather than using stale GPU resources. The prototype does not yet recreate a lost device or surface. GPU compute duration is read from timestamp queries only when the adapter supports them; CPU submission time is reported separately. See the [CPU/GPU contract](../specifications/cpu-gpu-contract.md) and [benchmark method](../research/first-light-benchmark.md).
