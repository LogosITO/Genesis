# World state

Foundation 0.7.1 adds at most one kinematic sphere to `WorldState`. It has a stable world ID, analytic radius, current centre, desired velocity, last displacement, and last contact. Tick-indexed input changes its velocity; only fixed-step simulation moves it. See the [kinematic contact contract](kinematic-contact.md).

`WorldState` stores ordinary analytic growing spheres, growth organisms, and resource sources in insertion order. `EntityId` is a shared monotonically assigned `u64`, stable for the world's lifetime and never reused. Each ordinary entity owns a `Sphere`, `Transform`, and nonnegative finite growth rate. Each organism owns stable local node IDs, parent links, a spendable budget, and a derived structural lifecycle. Each source owns a continuous influence field and, in finite mode, an authoritative reservoir ledger. Foundation 0.7 permits atomic removal of a non-root organism subtree; ordinary sphere/source removal, component systems, and general object types are not implemented. Invalid insertion or pruning leaves the world unchanged. `DeterministicSeed` is recorded in state; current rules do not consume randomness, so changing the seed does not change outcomes. See [First Interaction](first-interaction.md) and [ecosystem state](ecosystem-state.md).

The world exposes read-only access to entities, organisms, and sources. Controlled organism growth and source mutation preserve invariants. The simulation copies the world, validates proposed changes, and commits atomically. Versioned persistence belongs to `world-runtime`; direct deserialization into `WorldState` must be followed by `validate()` before use. See [growth](growth-model.md), [finite allocation](resource-allocation.md), and [persistence](world-persistence.md). This is a minimal state model, not a general ECS.
