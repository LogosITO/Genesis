# World persistence version 6

## Decision

`world-runtime` writes a JSON envelope with `format_version: 6` and the runtime state. It reads valid versions 1–5. For version 1, missing `max_children` defaults to 2 and missing shared `budget` defaults to zero. For versions 1 and 2, the former dense node allocation count becomes `next_node_id`; their nodes, parents, and energy remain intact. Versions 3–6 require a valid explicit `next_node_id` and may contain gaps after pruning. Older saves without a kinematic body load with `body: None`. Versions 1–4 have unlimited sources without a reservoir; a finite reservoir mislabeled as an older version is rejected. Versions 1–5 have no authored world instances; authored definitions, occurrences or events mislabeled as an older version are rejected. New saves are version 6, so older runtimes are not expected to read them. State includes fixed step, completed tick, seed, monotonic world ID allocator, sphere entities, organisms and sources, finite source ledgers where present, optional kinematic body state and last contact, shared exact-byte authored definitions and occurrence records, pending typed events including authored updates, and next event order. The format is inspectable but not a stable public interchange API.

Input is limited to 2 MiB before parsing; each authored definition is separately bounded to 65,536 source bytes. Unknown fields, malformed JSON, unsupported versions, nonfinite or invalid numeric state, duplicate world IDs, invalid authored hashes or semantics, dangling definition references, missing or forward node parents, cycles, excess children, invalid budget or lifetime allocator, exhausted capacities, and invalid or conflicting pending events are rejected. Gaps in world IDs are allowed after authored occurrence removal, but IDs are never reused. Loading constructs a complete candidate, recompiles each distinct authored revision, migrates only older supported versions, validates it, then returns or replaces state; a failed `load_into` leaves the current runtime untouched. Exact `f64` JSON round trips use Serde JSON's `float_roundtrip` parser feature.

`save_new` writes and syncs a temporary file in the destination directory, creates the final path by hard link, then removes the temporary name. It never overwrites an existing save. A failed write cannot corrupt a previous valid save at the same path. The filesystem must support hard links. A crash can leave a temporary file; directory entries are not synced and durable recovery after power loss is not guaranteed. To keep multiple checkpoints, choose distinct paths. The byte API lets an embedder use its own durable storage protocol.

## Limits

The file size cap bounds parser input, not process memory to the byte. The format contains no integrity signature or authenticated provenance. Checksums used by examples are diagnostics only. Loading untrusted saves should be subject to normal application-level file and resource controls. No migration from future versions is implemented.
