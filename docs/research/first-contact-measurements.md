# First Contact local measurements

**Environment:** Windows, Rust 1.94.0, release profile, NVIDIA GeForce RTX 4070 SUPER/Vulkan for the separate GPU readback test. CPU timings use 50 serial repetitions and report median / p95 milliseconds. They are local observations, not latency guarantees. Reproduce with `cargo test --release -p world-simulation contact_cpu_benchmark --locked -- --ignored --nocapture --test-threads=1`.

Candidate enumeration measures index collection, not intersection. Narrow-phase timing applies analytic sweeps only to BVH candidates whose conservative bounds overlap. Full query includes candidate collection and narrow phase. Full tick includes growth, ordinary sphere update, contact-scene construction, and body movement; it excludes rendering and presentation. The post-prune scene is a different workload and cannot isolate the benefit of BVH. In the small scene the BVH query is slower than direct; in the 380-solid scene its query is faster, but rebuilding every tick dominates the contact cost. The measured 381st rendered primitive is a non-solid source marker. Contact BVH and renderer GPU BVH are separate CPU/GPU-independent and renderer-specific acceleration structures, respectively.

Headless fixed-tick outcomes at tick 120, seed 7: `contact` first hits node 1 at tick 71 and stops at body z = −0.2078460979082653. `contact-pruned` cuts child 1 and disables the source at tick 60, encounters no contact on the same path, and reaches z = 0.9999999999999997. `contact-replay` saves and reloads at tick 80 and matches the pruned runtime exactly, including the body and event queue. These are authoritative state differences, not image-only effects. The 2000-tick test repeatedly prunes and regrows, validates topology and resource state every tick, checks bounded scene/save sizes, and compares uninterrupted and saved continuation. The allocator exhaustion test reaches its explicit 1024-ID lifetime limit without reusing IDs.

The opt-in GPU test rendered the authoritative body before and after a fixed tick to an offscreen texture. Direct and GPU BVH output matched after movement; before and after pixels differed. This checks visual state propagation, not collision on GPU. The native viewport and real input-to-contact flow require separate manual interaction verification. See the [contact contract](../specifications/kinematic-contact.md) for numerical limits and unsupported shapes.
