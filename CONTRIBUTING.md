# Contributing

This is an experimental research project. Before a change, read the [architecture](docs/architecture/overview.md) and relevant ADR. Keep analytic state authoritative; do not add renderer dependencies to core crates. Describe the mathematical contract, tests, limitations, and reproduction steps in a pull request. Run the four checks in the root README. Use the [experiment template](docs/research/experiment-template.md) for performance or numerical claims. Avoid speculative crates and dependencies. Contributions are offered under MIT OR Apache-2.0.

Use a [Conventional Commit](https://www.conventionalcommits.org/en/v1.0.0/) title for each pull request: `type(scope)!: summary`. The scope is optional; use a crate name (`field`, `renderer`, `world`, etc.) when useful. Examples: `feat(field): add analytic primitive`, `fix(world): retain entity identity`, `docs: clarify field sign`. Put `!` in the title for a breaking change and explain the migration in the PR body. Squash merges should use the PR title as the resulting commit subject. The CI title check accepts `feat`, `fix`, `perf`, `refactor`, `docs`, `test`, `build`, `ci`, and `chore`. See the [release policy](docs/architecture/releases.md) for version effects and the maintainer release process.
